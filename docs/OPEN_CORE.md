# Open Core 边界

本项目采用 **AGPL-3.0 + 商业授权**。客户端源码公开，付费服务和官方构建保持闭源/私有。

## 免费功能

以下功能不得依赖激活码，社区构建也必须可用：

- 启动已安装的 Minecraft 版本
- 已安装版本的管理、编辑、导入
- Java 管理
- 基础模组/资源包下载与安装
- 本地备份
- 基础更新（如构建注入了更新地址）

## 付费功能

授权码的 `features` 数组控制以下能力：

| feature | 能力 | 当前实现位置 |
| --- | --- | --- |
| `versions` | 下载新的 Minecraft 游戏版本 | 客户端下载器 |
| `server` | MCSM 服务器管理、备份、同步 | 客户端 API + 外部 MCSM |
| `lan` | 局域网发现、共享、同步 | 客户端 P2P |
| `ai` | AI 搜索与 OrcaRouter 登录 | 客户端调用外部 AI |
| `cloud` | 云同步、云备份 | 预留，服务端实现 |
| `cdn` | 整合包 CDN | 预留，服务端实现 |
| `hosting` | 服务器托管 | 预留，服务端实现 |
| `priority` | 优先支持 | 运营权益 |

`*`、`all`、`pro`、`commercial` 可作为通配权益，仅用于内部或全量授权。

## 关键原则

1. **客户端检查只负责 UI 和低成本防误用**。开源客户端中的 `requireFeature` 可以被修改；下载新游戏版本、付费服务等最终仍应由服务端/发布渠道控制。
2. **真正的付费边界在服务端**：云同步、CDN、托管、AI 代理等必须校验账号权益，不能只信任客户端。
3. **免费功能永远不能被 license 状态阻断**。`ready()` 不再检查授权。
4. **官方构建才包含商业产品配置**。社区构建没有 API Key/服务地址，显示“社区构建”。
5. **官方签名、更新源、品牌不随源码授权**。

## 构建类型

### 社区构建

公开 CI 默认产物：

```powershell
wails build
```

- 无产品 API Key/服务地址
- 免费功能完整
- 付费入口显示 PRO 提示
- 不含官方更新地址

### 官方/内部构建

在私有 CI 或本机注入：

```powershell
$env:MGL_PRODUCT_API_KEY = "..."
$env:MGL_PRODUCT_SERVER_URL = "https://..."
.scriptsuild-release.ps1 -Pack
```

- 产品配置只存在于构建产物和私有 CI secret 中，不进入公开仓库
- 加壳、签名、官方更新地址
- 只由官方发布渠道分发

## 服务端拆分

以下内容不在公开客户端仓库中：

- LicensingGo 服务端代码、JWT secret、数据库
- 支付/订单后台
- 云同步、CDN、托管服务
- OTA 私钥、代码签名证书、发布流水线 secret

客户端通过 HTTPS API 使用这些服务。服务端应独立鉴权、限流、审计，并只返回当前账号有权访问的数据。

## 为什么不是强 DRM

AGPL 允许用户修改和重新编译客户端。任何纯客户端授权判断都可以被移除。我们接受这一点，并把商业价值放在：

- 官方稳定构建
- 云服务和托管
- 内容 CDN
- 官方品牌与支持
- 服务端权益

这比在客户端堆叠反调试更可持续，也更符合开源协议。
